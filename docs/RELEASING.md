# راهنمای انتشار

## منبع نسخه

`src/shared/updates.js` منبع اصلی نسخه برنامه است. `UPDATES[0].version` نسخه جاری را تعیین می‌کند و
`APP_VERSION` از آن مشتق می‌شود. گردش‌کار Android همین مقدار را برای `versionName` و Release
استفاده می‌کند.

## آماده‌سازی انتشار

1. نسخه را طبق Semantic Versioning افزایش دهید.
2. ورودی جدید را در ابتدای `UPDATES` با تاریخ واقعی قرار دهید.
3. عنوان و تغییرات کامل را در `fa` و `en` بنویسید.
4. در صورت نیاز `CHANGELOG.md` و مستندات قابلیت را همگام کنید.
5. `npm run lint` و `npm run build` را اجرا کنید.
6. برای تغییر Android، sync و `assembleDebug` و سناریوهای native را بررسی کنید.
7. تغییرات را از نظر حریم خصوصی، permission، درخواست شبکه و خروجی PNG بازبینی کنید.

نسخه پیشنهادی:

- PATCH برای رفع باگ سازگار با قبل.
- MINOR برای قابلیت جدید سازگار با قبل.
- MAJOR برای تغییر ناسازگار در رفتار یا داده‌های ذخیره‌شده.

## انتشار خودکار

ادغام در `main` دو مسیر اصلی را فعال می‌کند:

- GitHub Pages خروجی Vite را build و deploy می‌کند.
- Android در صورت تغییر مسیرهای مرتبط، نسخه Gradle را همگام، APK را build و Release نسخه‌دار و rolling `latest` را منتشر می‌کند.

## بررسی پس از انتشار

- نسخهٔ آنلاین بدون خطا باز شود و assetهای قدیمی مانع راه‌اندازی نشوند.
- شماره نسخه و یادداشت تغییرات درست نمایش داده شوند.
- GitHub Release، نام APK و SHA-256 صحیح باشند.
- smoke test وب و Android انجام شود.
- در صورت مشکل، ابتدا انتشار معیوب را متوقف و سپس با یک patch شفاف اصلاح کنید؛ تاریخچه را
  بازنویسی یا artifact را بی‌توضیح جایگزین نکنید.

فقط نگه‌دارندهٔ دارای دسترسی مجاز باید secret، tag یا Release را مدیریت کند.
